# AstrBot 微博监控插件 (Weibo Monitor)

定时监控微博用户动态并推送到指定会话。  
由 Trae 配合 Gemini-3-Flash-Preview 和 MiniMax-M2.5 模型开发，DeepSeek-V4-Pro、MiniMax-M2.7、MiMo-V2.5-Pro 和 ChatGPT 5.6 模型进行后续维护和更新。

## 功能特性

- **定时监控**：自定义检查频率，支持间隔随机化避免被反爬。
- **多用户支持**：可同时监控多个微博账号，支持URL、UID、用户名三种输入格式。
- **精准推送**：仅推送最新更新，自动过滤置顶微博。
- **Cookie 配置**：必须配置微博 Cookie 才能正常抓取数据，确保稳定性。
- **灵活过滤**：支持屏蔽词过滤、白名单关键词过滤，可选择是否推送原创/转发微博。
- **消息自定义**：支持自定义推送消息格式，满足不同需求。
- **配置导入导出**：支持配置的导入导出，方便迁移和备份。
- **数据持久化**：自动持久化监控数据，重启后不会重复推送历史微博。
- **错误恢复**：内置请求重试和异常处理机制，保证监控稳定性。
- **运行日志**：支持滚动记录运行日志，方便排查问题。
- **Cookie 健康检查**：在抓取前自动检测 Cookie 有效性，失效时会向用户发送一次提醒，避免抓取静默失败。
- **每日记录与总结**：记录每日推送的微博动态，并定时推送前一天的监控总结。初始化监控时，自动记录历史微博，避免历史微博丢失。
- **热搜监控**：定时推送微博热搜榜前 N 条（默认无需 Cookie，遇风控自动兜底），支持过滤广告位，间隔和数量可配置。
- **订阅分组管理页面**：在插件详情中以表格管理会话订阅；`*` = 接收所有已监控博主，指定 UID = 只收该博主。热搜和每日总结可在页面中按会话独立勾选。
- **推送统计**：订阅分组页面提供近 7 天的日期切换、24 小时时段分布和博主推送排行，统计实际成功发送到至少一个会话的微博动态。
- **图文推送**：自动获取微博原图（最高清画质），文字与图片分别独立发送以兼容所有平台（QQ、KOOK、飞书等）。支持配置每条微博最多获取的图片数量。
- **视频推送**：自动检测微博中的视频（含转发微博），流式下载后推送到目标会话。支持 720p / HD / LD 清晰度自动选择，可配置大小限制。
- **单条微博抓取**：通过 `/weibo_get` 命令，可抓取并推送任意微博链接的内容（含图片）。

## 部署步骤

1. **安装**：
   在 AstrBot 插件市场安装本插件。
   插件会自动安装 `requirements.txt` 中的依赖。如果手动安装，请在服务器环境下运行：
   
   ```bash
   pip install httpx beautifulsoup4
   ```

2. **获取会话 ID (unified_msg_origin)**：
   在你想接收推送的会话（群聊或私聊）中，向机器人发送指令：
   
   ```
   /weibo_umo
   ```
   
   机器人会返回当前会话的 ID，请记录下来。

3. **配置插件**：
   在 AstrBot 管理面板 -> 插件设置 -> `weibo_monitor` 中，按卡片配置 Cookie、监控频率、微博推送内容、图片与视频等项目。`weibo_cookie` 为必填项。

4. **配置监控与推送目标**：
   打开本插件详情页的 **订阅分组管理** Page：
   
   - 先在“监控博主”中添加需要抓取的微博 UID 或主页链接。
   - “全部微博博主”表示 `会话ID: *`，即接收所有已监控博主的微博。
   - “仅指定博主”会显示已监控账号的勾选列表，直接勾选需要接收的博主即可。
   - 热搜和每日总结在同一行单独勾选，与微博接收范围无关。
   - 通过 `/weibo_umo` 获取的会话 ID 即使包含冒号，也可以直接填写；页面会自动正确识别订阅范围。
   - 页面会阻止空会话、重复会话和无效 UID；旧版异常行会先提示，确认后才会移除。

## 关键词过滤规则

本插件提供两种关键词过滤方式：**屏蔽词（黑名单）** 和 **白名单**。

### 屏蔽词（filter_keywords）

包含屏蔽词列表中任意关键词的微博将**不会**被推送。

**示例：**

- 设置屏蔽词为 `["广告", "推广", "兼职"]`
- 包含"广告"、"推广"或"兼职"的微博会被跳过，不会推送

### 白名单（whitelist_keywords）

只有微博正文包含白名单中任意一个关键词时才会推送。

**示例：**

- 设置白名单为 `["预告片", "投票", "抽奖"]`
- 只有包含"预告片"、"投票"或"抽奖"这些关键词的微博才会被推送
- 其他微博会被跳过，不会推送

### 过滤优先级

**先检查屏蔽词，后检查白名单。** 具体逻辑如下：

1. **第一步：黑名单检查（屏蔽词）**
   
   - 如果微博包含任意一个屏蔽词 → **直接跳过，不推送**
   - 如果微博不包含任何屏蔽词 → 进入第二步

2. **第二步：白名单检查（关键词白名单）**
   
   - 如果白名单为空 → **允许推送**（通过第一步的微博）
   - 如果白名单非空 → 必须包含至少一个白名单关键词才允许推送

**流程总结：**

```
微博内容
    ↓
是否包含屏蔽词？ → 是 → [不推送]
    ↓否
白名单是否为空？ → 是 → [推送]
    ↓否
是否包含白名单关键词？ → 是 → [推送]
    ↓否
[不推送]
```

这样设计的目的是：

- **屏蔽词优先**：保护用户不受垃圾内容的打扰，这是最重要的过滤
- **白名单补充**：在通过屏蔽词过滤后，进一步只推送用户关心的内容

## 自定义消息格式

你可以在插件设置的 `message_format` 中自定义推送消息的样式。支持以下变量：

- `{name}`: 微博用户的昵称。
- `{weibo}`: 微博正文内容（已自动处理换行）。
- `{link}`: 微博原文链接。

**默认格式示例：**

```
🔔 {name} 发微博啦！

{weibo}

链接: {link}
```

## 热搜监控

热搜监控功能默认关闭，开启后可定时推送微博热搜榜前 N 条，**默认无需配置 Cookie 即可使用（遇风控拦截时会自动使用配置好的 Cookie 兜底）**。

### 热搜消息格式

你可以在插件设置的 `hotsearch_message_format` 中自定义热搜推送的样式。支持以下变量：

- `{top_n}`: 当前推送的热搜条数。
- `{time}`: 推送时间。
- `{items}`: 热搜条目列表（包含排名、标题及跳转链接）。

此外，`hotsearch_show_link` 配置项可控制每条热搜下方是否显示微博搜索链接。关闭后每条热搜仅显示序号和标题，推送消息更简洁。

**默认格式示例：**

```
🔥 微博热搜榜 Top {top_n}
⏰ 更新时间: {time}

{items}
```

**实际推送效果：**

### 热搜日志记录

开启 `enable_daily_log` 后，每次热搜推送都会记录到 `logs/YYYYMMDD.log` 文件中（JSON 格式，`type: "hotsearch"`）。每日总结中也会统计当天的热搜推送次数。

注意：热搜推送**不会**在初始化监控时自动记录历史数据（与微博动态不同），仅在每次推送时实时记录。

## 推送目标与订阅分组

`subscription_mappings` 决定每个会话接收全部微博博主还是指定博主；热搜和每日总结则由该会话的独立勾选项决定。

从 v1.19.0 起，请在插件详情页打开 **订阅分组管理** Page 统一管理监控博主和订阅分组；原生插件配置页中的相关字段仅用于兼容存储，不建议手动修改。

### 一分钟上手

| 你想干什么      | 怎么写                 |
| ---------- | ------------------- |
| 一个群接收所有博主  | 选择“全部微博博主”          |
| 一个群只接收某个博主 | 在勾选列表选择博主           |
| 两个群各自收不同博主 | 两行，每行指定不同 UID       |
| 指定谁接收热搜或总结 | 单独勾选该会话的“热搜”或“每日总结” |

**关键点**：

- “全部微博博主” = 该会话接收所有已监控博主的微博
- “仅指定博主” = 直接勾选已监控账号，选择要接收的微博
- 热搜和每日总结分别由当前会话的勾选框决定，和微博接收范围相互独立
- **一个会话只写一行**，不要同一个会话 ID 出现在多行里

### 真实案例

**小明想给粉丝群推送李佳琦和罗永浩的微博：**

```
# 先 /weibo_umo 拿到群ID，假设是 group_fans123
group_fans123: *
```

> 小明的群会收到李佳琦每条微博 + 罗永浩每条微博；是否接收热搜榜和每日总结，由该行的两个勾选框决定。

**小红管理两个群，大群收全部，管理群只收李佳琦：**

```
group_big_fans: *
group_admin: 2534531481
```

> 大群和管理群的热搜、每日总结接收权限可以分别勾选，不再受微博订阅范围限制。

**小刚有 3 个群，每个群追踪不同明星的微博：**

```
group_fans_A: 1234567890
group_fans_B: 9876543210, https://weibo.com/u/1111111111
group_fans_C: 2534531481, 5310078607, https://weibo.com/n/某明星
```

> 每个群只看自己关心的博主；热搜和总结可按群单独开启。

### 从旧版升级指南

> **自动迁移**：v1.17.0 会在首次启动时自动把 `target_conversation_id` 里的全局目标转为 `会话ID: *`。你什么都不用做。

| 旧配置                                                    | 自动变成                         |
| ------------------------------------------------------ | ---------------------------- |
| `target_conversation_id: [群A]`                         | `群A: *`                      |
| `target_conversation_id: [群A, 群B]` + `sub: [群C: uid甲]` | `群A: *`  `群B: *`  `群C: uid甲` |
| `sub: [群A: uid甲, 群B: uid乙]`（无 target）                  | 不变                           |

升级到 v1.19.0 后，无需修改已有微博订阅范围；可直接在订阅分组页面维护监控博主，并为会话勾选热搜或每日总结。

## 常用指令

- `/weibo_umo`: 获取当前会话 ID（用于配置推送目标）。
- `/weibo_verify`: 验证当前设置的 Cookie 是否有效。
- `/weibo_check`: 立即抓取列表里第一个账号并推送最新一条微博。
- `/weibo_check_all`: 立即抓取列表里所有账号并推送最新一条微博。
- `/weibo_status`: 查看当前监控状态（监控账号数、推送目标、检查间隔等）。
- `/weibo_summary`: 手动触发昨日总结推送。
- `/weibo_hot`: 手动查询当前微博热搜榜（需先开启热搜监控功能）。
- `/weibo_export`: 将当前插件的所有配置导出为 Base64 字符串。
- `/weibo_import [配置字符串]`: 使用导出的配置字符串快速恢复或迁移配置。
- `/weibo_cookie [Cookie字符串]`: 直接通过命令更换微博 Cookie，更换后自动验证并尝试重载插件。
- `/weibo_get [微博链接]`: 抓取并推送指定链接的微博内容（含图片）。支持 `weibo.com` 和 `m.weibo.cn` 的多种链接格式。

## 重要说明

### Cookie 必填提醒

⚠️ **微博Cookie为必填项**，插件虽然允许在未配置 Cookie 时启动，但**必须配置 Cookie 后才能正常抓取数据**。请务必按照下方步骤获取并配置Cookie。

### 如何获取微博 Cookie

1. 在电脑浏览器打开 [微博移动端官网](https://m.weibo.cn/) 并登录。
2. 按 `F12` 打开开发者工具，切换到 `网络 (Network)` 选项卡。
3. 刷新页面，在左侧列表中找到第一个 `m.weibo.cn` 的请求（或者任何一个 `getIndex` 请求）。
4. 在右侧的 `请求标头 (Request Headers)` 中找到 `Cookie` 字段。
5. 复制该字段的完整值，粘贴到插件设置的 `weibo_cookie` 中。

### Cookie 注意事项

- Cookie具有有效期，失效后需要重新获取
- 请勿在多设备同时登录同一账号，可能导致Cookie失效
- 获取Cookie时请确保使用微博移动端官网 (m.weibo.cn)，而非PC端官网
- 配置完成后可使用 `/weibo_verify` 指令验证Cookie是否有效

## 常见问题

**Q: 为什么配置了Cookie还是抓不到数据？**  
A: 请先使用 `/weibo_verify` 指令验证Cookie是否有效。如果Cookie有效但仍无法抓取，请检查：

1. 微博URL格式是否正确
2. 检查间隔是否设置过短导致被反爬
3. 查看日志是否有其他错误信息

**Q: 为什么会重复推送相同的微博？**  
A: 正常情况下插件会自动记录最后推送的微博ID，不会重复推送。如果出现重复推送，可能是：

1. 插件数据文件损坏或丢失
2. 微博ID发生变化（极少情况）
3. 可以使用 `/weibo_check` 指令手动检查是否重复

**Q: 如何提高监控稳定性？**  
A: 建议：

1. 检查间隔设置为10分钟以上
2. 启用间隔随机化（设置check_interval_jitter和request_interval_jitter）
3. 定期更新Cookie，避免失效
4. 监控账号数量不宜过多

**Q: 在哪里可以找到日志文件？**  
A: 请检查AstrBot/data/plugin_data/astrbot_plugin_weibo_monitor目录下的plugin.log文件。
